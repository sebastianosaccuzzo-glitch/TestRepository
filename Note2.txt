checked 
controllo su operatore aritmetico, da eccezione se va in overflow (OverflowException)
(cioè se si assegna un valore superiore al valore massimo della locazione di memoria prefissa (es. int) )
Default le operazioni sono unchecked, e se superano il valore(nessuna eccezione) torna la differenza (ricomincia da capo, esegue il wrapping dal valore massimo al valore minimo.)
Con checked => se overflow da eccezione -> OverflowException
Es. 
uint a = uint.MaxValue;
unchecked { Console.WriteLine(a + 3);  // output:  }
try {
    checked {   Console.WriteLine(a + 3);    }
} catch (OverflowException e)
{    Console.WriteLine(e.Message);  /*output: Arithmetic operation resulted in an overflow.*/}

public IEnumerable<int> TakeWhilePositive(IEnumerable<int> numbers)
{
    foreach (int n in numbers)
    {
        if (n > 0) yield return n;
        else yield break;
    }

Assembly
(dll)
- Assembly.LoadFrom(string path)
- Assembly.Load(byte[] rawAssembly)
o Cosa fa: Carica un assembly direttamente dalla memoria, leggendolo come un array di byte (ad esempio se scarichi la DLL da un database o da una chiamata di rete).
- Assembly.GetExecutingAssembly()
o Cosa fa: Estrae l'assembly in cui è scritto il codice che stai eseguendo in quel preciso momento (nel tuo caso, il progetto WCF stesso).
- Assembly.GetCallingAssembly()
o Cosa fa: Estrae l'assembly che ha chiamato il metodo corrente (utile se ti trovi dentro una libreria di utility comune e vuoi sapere chi ti sta usando).
- Assembly.GetEntryAssembly()
o Cosa fa: Estrae l'assembly di partenza dell'intera applicazione (l'eseguibile principale .exe). Nota bene: sotto IIS/IISExpress questo metodo restituisce spesso null perché l'entry point è il processo di IIS (w3wp.exe o iisexpress.exe).
- AppDomain.CurrentDomain.GetAssemblies()
o Cosa fa: Non restituisce un solo assembly, ma un array (Assembly[]) di tutti gli assembly che sono già stati caricati in memoria dall'applicazione in quel momento.

Mode:
Ecco i principali tipi/modi di binding che puoi trovare in XAML (specialmente in WPF, UWP, Xamarin.Forms):
1. OneWay Binding
La sorgente dati aggiorna la destinazione. (La UI riflette i dati, ma non il contrario).
2. TwoWay Binding
La sorgente dati e la destinazione si aggiornano a vicenda. Utile per moduli/modifica dati.
3. OneWayToSource Binding
Solo la destinazione aggiorna la sorgente (il contrario di OneWay).
4. OneTime Binding
Il binding si risolve solo una volta all’inizio, non si aggiornano più i dati.
5. Default Binding
Usa il comportamento predefinito della proprietà (di solito OneWay o TwoWay, a seconda della proprietà).

StaticResource
( richiama i componenti definiti nel Resources (locale o globali o in tutta l’applicazione) )
Fornisce un valore per qualsiasi attributo di proprietà XAML cercando un riferimento a una risorsa già definita. Il comportamento di ricerca per tale risorsa è analogo alla ricerca in fase di caricamento, che cercherà le risorse precedentemente caricate dal markup della pagina XAML corrente e da altre origini dell'applicazione, e genererà tale valore della risorsa come valore della proprietà negli oggetti in tempo di esecuzione.
( Usato nello xaml, per chiamare elementi nello stesso xaml, es. template, converter,etc)
Locale (nel singolo xaml)
<Window x:Class="index.Window1"
        xmlns="http://schemas.microsoft.com/winfx/2006/xaml/presentation"

* Definisce
Class HostService{
ServiceHost Host=null;
Thread _thread;
ServiceHost SetHost(string url, object instanceService)
{ SericeHost item= new ServiceHost(instanceService, new Uri(url));
var behaviour=item.Description.Behaviors.Find<ServiceBehaviorAttribute>();
behavior=InstanceContextMode=InstanceContextMode.Single; // crea solo una istanza °° per qualsiasi sessione
Host=item;
return item;}
void Start(){
_thread=new Thread(()=>Host.Open());
_thread.Start();}

Void Stop(){
Host?.Close();
_thread.Join();}
