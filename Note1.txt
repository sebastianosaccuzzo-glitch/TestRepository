o Il meccanismo del "Buffering" di rete
o Il database non "spara" tutti i milioni di righe in una volta sola nella RAM del tuo server applicativo. Il driver del database (il Provider ADO.NET):
* .. Apre una connessione e mantiene un cursore aperto sul database.
* .. Riceve i dati a blocchi (chiamati TDS packets o fetch buffer).
* .. Mentre tu fai foreach, il driver legge i dati già arrivati nel buffer locale. Quando il buffer si svuota, il driver chiede al database il "pezzo" successivo della stessa query.
* .. Sì, durante uno streaming LINQ verso un DB, la connessione rimane occupata e aperta finché non hai finito di scorrere tutti i dati o non chiudi l'enumeratore.
* Questa sezione contiene le parole chiave contestuali usate nelle espressioni di query.

Modificatori (di comportamento)
Virtual
Virtual è posto in metodi/proprietà Padre e nel figlio si mette override. (segna che quel metodo/proprietà è sovrascrivibile (dai figli) ) 
Parola chiave che permette di usare un metodo/proprietà/etc figlio e non quella padre tramite ereditarietà
Principalmente usata per quando si usa il polimorfismo.

Class C1 {int virtual Get(){…}}  // => -1
Class C2 : C1{int  override Get(){…}} // => 1
Se si usa:
C1 c1=new C2(); int x=c1.Get(); 
// x=1 se si mette virtual (lo prende dal figlio C2) ,, 
// x=-1 se non ha virtual (e si prende l’istanza del padre (dell’oggetto di  c1) )
Abstract, override
* Abstract posto in metodi/proprità di classi abstract ( public abstract class C1{…})
o Es. public abstract void Work();  
o I figli che implementano si mette override
* Override, usato per qualsiasi metodo/proprietà per sovrascrivere da:
o Interface, abstract, class

Overriding 
Riscrittura di un metodo.
Una classe figlia (derivata) eredita dalla classe padre un metodo e lo vuole sovrascrivere con il proprio.
Entrambi le parti (padre e figlia) devono essere concordi al sovrascrivere il metodo : il padre con la keyword: virtual/abstract, la figlia con: override ( se no da warning).
Figlia => metodo1, metodo2, metodoPadre(sovrascitto)
* e.g. 
o padre=> p.c int virtual MethodPadre()=>0;
o figlia => p.c int override MethodPadre()=>2;
Supporta un corretto uso del polimorfismo 
* e.g. 2
Padre p=new Figlia();
p.MethodPadre(); // => 2, perché figlia l’ha sovrascritto
 new=> Shadowing (Method Hiding)
Metodo nascosto, (versione diversa di overriding).
Nasconde il metodo padre con lo stesso nome, e rende visibile il proprio.
Figlia => metodo1, metodo2, metodoPadre(new, il proprio), methodPadre(nascosto)
* e.g. 
o padre=> p.c int MethodPadre()=>0;
o figlia => p.c int new MethodPadre()=>2;
Non supporta un corretto uso del polimorfismo 
* e.g. 2
Padre p=new Figlia();
p.MethodPadre(); // => 0, perché figlia non l’ha sovrascritto, e al livello del padre il metodo nascosto è visibile
Con il ‘new’ si potrebbe riscrivere una funzione con stesso nome ma con  diversa firma e ciò che ritorna.
* E.g. 3
o padre=> p.c int MethodPadre()=>0;
o figlia => p.c string new MethodPadre()=>”figlia2”;
